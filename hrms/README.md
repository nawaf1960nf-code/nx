# نظام إدارة الموارد البشرية (HRMS)

نظام متكامل لإدارة الموارد البشرية مبني للعمل في بيئة المملكة العربية السعودية،
يعمل كموقع ويب وتطبيق موبايل (PWA). يغطي بيانات الموظفين والهيكل التنظيمي
والحضور والإجازات والرواتب ونهاية الخدمة وتقييم الأداء والتقارير.

## التقنيات

| الطبقة            | التقنية                                                        |
| ----------------- | -------------------------------------------------------------- |
| الواجهة           | React + TypeScript + Tailwind CSS + Zustand + React Query      |
| الموبايل          | PWA (Service Worker + Manifest)                                |
| الخلفية           | Node.js + Express + TypeScript                                 |
| قاعدة البيانات    | PostgreSQL + Prisma ORM (مع حذف منطقي عبر Middleware)          |
| التحقق من المدخلات | Zod                                                           |
| الأمان            | JWT + Refresh Tokens + bcrypt + Helmet + Rate Limit            |
| الفورية والطوابير | Socket.io + BullMQ/Redis                                       |
| تخزين الملفات     | MinIO / S3                                                     |

## ملاحظات حول منطق العمل

### نهاية الخدمة (EOSB)

يطبّق `eos.service.ts` نظام العمل السعودي:

- **المادة 84:** أجر نصف شهر عن كل سنة من الخمس الأولى، وأجر شهر كامل عن كل
  سنة تالية، مع احتساب كسور السنوات بالتناسب.
- **المادة 85:** تخفيض مكافأة الاستقالة (لا شيء دون سنتين، الثلث حتى خمس
  سنوات، الثلثان حتى عشر سنوات، وكاملة عند عشر سنوات فأكثر).
- يدعم تقدير المخصصات المستقبلية (Provision) للتقارير المالية.

### الحضور (GPS & Geofencing)

يتحقق `attendance.service.ts` من وقوع موقع الموظف ضمن نطاق الفرع باستخدام
صيغة Haversine، ويحسب التأخير والتبكير والعمل الإضافي آلياً وفق الوردية
وسياسة الحضور، مع دعم الورديات الليلية.

### التقارير

يوفّر `reports.controller.ts` تقارير قياسية (تعداد الموظفين، مخصص نهاية
الخدمة) وتقارير ديناميكية يختار فيها المستخدم الأعمدة والفلاتر ويصدّرها
بصيغة JSON أو CSV، مع قوائم سماح صارمة للحقول لضمان الأمان.

### محرّك الأتمتة (Background Jobs)

تعمل مواقيت `node-cron` بتوقيت الرياض كمشغّل خفيف يضيف المهمة إلى طابور
`BullMQ`، بينما ينفّذ الـ Worker المنطق خارج مسار الطلبات. المهام المجدولة:

| المهمة | الموعد (بتوقيت الرياض) | الوظيفة |
| ------ | --------------------- | ------- |
| `accrue-leave` | أول كل شهر 00:05 | استحقاق أرصدة الإجازات (سنوي/شهري حسب نوع الإجازة) مع الترحيل |
| `check-absentees` | يومياً 11:00 | رصد الموظفين بلا حضور وإشعار المدير والموارد البشرية |
| `check-expiring-documents` | يومياً 08:00 | تنبيه قرب انتهاء المستندات والإقامة والعقود (خلال 30 يوماً) |

تُشغَّل من مرحلة إقلاع السيرفر عبر `startScheduler()`، ويمكن تشغيل أي مهمة
يدوياً عبر `triggerNow(name)`. وكل مهمة محميّة من التكرار خلال اليوم نفسه
عبر سجلّ في جدول `SystemSettings` بالإضافة إلى `jobId` يومي في الطابور.

### الأمان على مستوى الحقول (Field-Level RBAC)

التحكم بالصلاحيات لا يقتصر على الصفحات بل يمتد إلى الحقول:

- **الخادم** (`middleware/fieldFilter.ts`): يعترض `res.json` ويزيل الحقول
  المالية والبنكية (الراتب الأساسي والبدلات واسم البنك والآيبان وكامل حقول
  سجل الرواتب) من أي كائن في شجرة الاستجابة قبل إرسالها، إذا لم يكن الدور
  `HR_ADMIN` أو `SUPER_ADMIN`. الإزالة فعلية فلا تصل القيمة للعميل أصلاً،
  والمبدأ الافتراضي عند غياب المستخدم هو عدم الكشف.
- **الواجهة** (`components/shared/EmployeeProfile.tsx`): تبويب "المعلومات
  المالية" لا يُبنى ولا يُدرَج في الـ DOM إلا عند توفّر صلاحية `FINANCIAL_VIEW`
  (عبر شرط React وليس إخفاءً بـ CSS)، استناداً إلى خطّاف `usePermissions`
  وخريطة الأدوار في `lib/permissions.ts`.
